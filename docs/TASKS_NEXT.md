## 순서를 이렇게 잡은 이유

기준은 하나다. **나중에 하면 비용이 늘어나는가?**

| | 지금 해야 하는 것 | 나중에 해도 되는 것 |
|---|---|---|
| 판단 | 저장 형식(`schemaVersion`)을 바꾸거나, 두 렌더러가 **공유해야** 하는 것 | 이미 있는 도메인 위에 **화면만** 얹는 것 |
| 예 | 문단 줄바꿈 계산, 셀 단위 바인딩 | 드롭다운, 포맷 입력칸, 서식 복사 |
| 미루면 | 만들어 둔 기능을 전부 다시 검증해야 한다 | 비용이 그대로다 |

**"기능을 다 만들고 나중에 다듬는다"가 이 프로젝트에서 특히 위험한 이유**는,
지금 캔버스와 PDF가 **서로 다른 코드로 서로 다르게 틀리고 있기** 때문이다(P0-8).
요소가 7종인 지금 두 경로를 합치는 비용과, 기능을 더 얹은 뒤 합치는 비용은
선형으로 벌어진다. 그리고 그 사이에 만든 모든 기능은 두 번 검증해야 한다.

무엇보다 **지금은 발행하면 안 되는 문서가 나온다.** 기능을 넓혀도 발행은 여전히
못 하므로, 넓히는 동안 제품 가치는 0에서 움직이지 않는다. 반대로 1단계를 끝내면
"한 종류라도 제대로 발행되는" 상태가 되고, 그때부터 기능 하나가 가치 하나로 붙는다.
